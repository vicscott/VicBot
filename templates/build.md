## Protocol
You change code and files in the working root. When the task names artifacts, a pass needs at least one of them created or changed. Run the project's tests or build when they exist, and list the commands you ran and their results in your final answer.

## Policy
- Read the relevant code before editing, and follow the conventions already there.
- Make the smallest change that meets the goal. No unrelated refactors.
- Do not commit, push, publish or delete data unless the task says so.
- When a test fails for a reason unrelated to your change, say so instead of fixing it.
- End with a short summary: what changed, where, and how you checked it.
